# Board Race 开发交接

状态：主分支已切换为“单人 / 双打”，终局资格与失败结算名次已修复，等待发布后的实体双手柄试玩。

## 当前工作包

- 封存旧的固定分屏工位玩法：`archive/team-expedition-it-takes-two` 已独立保存；`main` 的玩法目录只进入单人或双打。
- 双打复用单人六艇竞速：两名玩家占用左、右席，四名 AI 补齐阵容；选角前完成设备入座，席位和设备在整局保持固定。
- 双打使用一根左摇杆的完整向量：X 轴转向、Y 轴前进 / 制动倒车，松杆保持自动前进；键盘左区 `W/A/S/D`，右区方向键。
- 玩家飞行失败时只淘汰该席，幸存者继续比赛并接管镜头、路线提示和 Final；淘汰席获得带冷却 / 库存的 `Q/E` 或 `U/O`（手柄 `B/Y`）互动。
- 荣誉系统由 `HonorTargetSystem`、`HonorLedger` 和 `HonorHighlights` 组成：大型目标、超车 / 飞行 / 互动 / 逆风等事件写入稳定 id，赛后先播 `PLAY OF THE RUN`，再展示六人名次、最多四张卡和结果 DTO。
- Final 门只接受完成全部七条飞行路线并完成 recovery 的赛车手；未合格的落后一圈船穿过同一物理门线不会再被标成完成。失败结算会在生成结果 DTO 前重排当前固定步名次；单人和双打均走同一荣誉墙。
- 鸭子气球爆破音量已提高，羽毛和气球采用更大幅度螺旋轨迹；双打 HUD 常驻两席控制条，明确不使用 `RT/LT` 推进。

## 已验证

- `npm run typecheck`
- `npm run build`
- `npm run verify:smoke`
- `verify:smoke` 额外锁定：未完成七飞的四名对手穿过 Final 不计完成；合格对手仍按亚帧先后排名；单人结果生成单席荣誉 DTO、两张有效卡和当前固定步名次。
- `npm run verify:collision`
- `npm run verify:audio`
- `npm run verify:team`：键盘双席、两只标准手柄、斜向左摇杆、RT/LT 隔离、淘汰接管、支援 / 浪花、荣誉结算和非空画面。
- 桌面 1440x900 与横屏 844x390 启动截图已复核；赛后荣誉墙实际触发截图已复核。

## 遗留风险

- 自动化只能模拟标准 Gamepad API；需要两名玩家用实体手柄确认摇杆回中、陡角斜向入座、Start 暂停和震动强度。
- 荣誉目标是程序化美术，后续替换素材必须保留目标 id、碰撞半径和事件池合同。
- 主分支仍保留少量 `teamExpedition` 兼容代码供封存分支读取；不得重新把它接回玩法目录。
